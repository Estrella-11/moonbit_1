# AI 辅助开发透明度说明

> 本文档回应《2026 年 9 月 MoonBit 黑客松大赛章程》对**可解释性**的要求：
> AI 可用于代码生成、接口设计、测试补全和文档撰写，但最终的项目目标、技术
> 路径、质量边界与开源合规由参赛者把控。

MoonDocKit 在开发过程中使用了 AI 工具。本文件记录 AI 参与了什么、人把控了
什么、以及每一条声明如何在本仓库中被独立复核。所有结论都可以用命令重新
验证，不依赖作者的自述。

## 一、AI 参与的环节

| 环节 | AI 的角色 | 人的角色 |
|------|-----------|----------|
| 实现草稿 | 生成函数初稿、重复逻辑的批量重构建议 | 决定是否采纳；重排模块边界与命名 |
| 测试补全 | 生成边界用例（空输入、单页、重复内容等） | 审定断言语义，删除无意义断言 |
| 文档撰写 | 起草文档段落、统一术语与表格格式 | 核对每个数字与命令，删除未经测量的表述 |
| 仓库检查 | 扫描过期指标、失效链接、格式漂移 | 确认修复范围，拒绝无关的大范围改写 |

AI 产出**没有**直接合入 `main`。每一处改动都必须先通过下文的验证护栏。

## 二、由参赛者把控的部分

以下内容**不由** AI 决定，任何与之冲突的 AI 建议都被拒绝：

- **项目目标**：做 MoonBit 生态的文档工具，而不是又一个通用 Markdown 解析器。
- **架构边界**：领域逻辑全部留在 MoonBit；JavaScript 只做文件系统适配层。
- **公开 API 边界**：以 `pkg.generated.mbti` 为准，接口变更视为破坏性变更。
- **验收标准**：`quality-report.json` 的检查项与发布门禁阈值。
- **开源合规**：Apache-2.0 许可证、第三方来源标注、来源可追溯。
- **最终评审**：逐个 commit 审阅，必要时回退（见下节）。

## 三、验证护栏

任何改动——无论是否由 AI 起草——都必须通过同一套门禁：

```bash
moon fmt && git diff --exit-code      # 格式一致
moon info && git diff --exit-code     # 公开接口与源码一致
moon check                            # 主目标编译无错
moon check --target js                # JS 目标编译
moon test                             # 全部测试通过
moon run cmd/main                     # 可运行示例
python tools/test_cli.py              # CLI 场景
python tools/verify_project.py        # 一次性全量验收
```

CI（`.github/workflows/ci.yml`）在每次推送时执行这些检查，因此评审无需信任
本文件的陈述，直接看 CI 状态即可。

## 四、AI 生成的成果如何被修正

诚实记录本轮开发中 AI 产出被修正或回退的情况：

| 问题 | 处理 |
|------|------|
| 重构后文档中的测试数与代码行数未同步更新 | 全部重新测量后修正（118 → 139 测试等），见 `docs/award-benchmark.md` |
| 建议把 `package_theme` / `api_reference_theme` 一起改成新配色 | **拒绝**。这是 API 契约变更，不是清理，需独立评审 |
| 建议把 `index.html` 改造成品牌落地页 | **拒绝**。该页是 `content="0"` 的跳转页，视觉收益约为零而回归风险不为零 |
| 建议顺手重写 Markdown 解析器 | **拒绝**。超出本次范围，见 `docs/award-sprint.md` 的 Avoid 清单 |

被拒绝的建议同样记录在案，用于说明"人把控"不是一句口号。

## 五、对 AI 能力的诚实限定

`ai/` 目录提供的是**基于规则的基线实现**，不是对大语言模型的真实调用：

- 所有 AI 功能**无需 API key** 即可运行，结果确定、可复现。
- `AiConfig` 与 `ai_prompts.mbt` 是为未来接入 OpenAI 兼容接口预留的，目前
  只做提示词模板与请求 JSON 构造。
- 因此评审不应把 `--ai-*` 输出理解为"模型生成的内容"，而应理解为**确定性
  的文档分析规则**。

这一限定是刻意的：在无网络、无密钥的评审环境中，可复现的证据比不确定的
智能更有价值。

## 六、已知的技术债

| 项 | 状态 | 说明 |
|----|------|------|
| `moon check --target js` 的 4 条 JS FFI 弃用告警 | 未修，已定位 | `Array` 应改 `FixedArray`；涉及 CLI 主路径上的两处调用点，需配合工具链版本固定一并处理。精确位置见 `docs/award-benchmark.md` |
| 真实第三方包的采用案例 | 未完成 | 当前采用证据来自仓库内置夹具，见 `docs/adoption-case-study.md` |

未修的原因与位置均公开记录，而不是静默忽略。

## 七、复核方式

```bash
# 1. CI 是否全绿
#    https://github.com/Estrella-11/moonbit_1/actions

# 2. 提交历史是否连续、语义化
git log --oneline

# 3. 公开接口是否与源码一致
moon info && git diff --exit-code

# 4. 全量验收
python tools/verify_project.py
```

若上述任一步失败，本文件的声明即不成立。
