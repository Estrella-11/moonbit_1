# Markdown 支持范围（边界声明）

> 本文是 MoonDocKit 对 **Markdown 子集** 的诚实边界声明。它列出渲染器（`moondockit.mbt`
> 的 `parse_body_blocks` / `render_inline` / `render_blocks`）当前**实际支持**的特性，以及
> **明确不支持**的特性。每一项都以源码实现为准，可用 `moon test` 与 Playground 复现，
> 不依赖主观描述。

设计目标是「文档站点」而非「通用 Markdown 编辑器」：优先保证标题、段落、列表、
代码块、引用与基础行内格式稳定、可发布、且对 XSS 安全。超出该范围的语法会被
**原样转义或当作普通文本**，不会崩溃，但也不会呈现预期效果。

---

## 一、支持的块级语法

| 语法 | 是否支持 | 规则与边界 |
|------|----------|------------|
| 标题 H1–H3 | ✅ | 仅 `# `、`## `、`### `（井号后必须有一个空格）。 |
| 标题 H4–H6 | ❌ | `####` 及以上不被识别，会被当作普通段落渲染。 |
| 段落 | ✅ | 空行分隔；段内软换行在输出中合并为空格。 |
| 无序列表 | ✅ | 仅 `- ` 一种前缀（短横 + 空格）。 |
| 有序列表 | ❌ | `1. ` / `a. ` 等不被解析，会当作段落。 |
| 嵌套 / 多级列表 | ❌ | 遇到非 `- ` 行即结束当前列表；缩进不表示层级。 |
| 围栏代码块 | ✅ | ```` ``` ```` 包裹；可带语言标识（如 ```` ```moonbit ````），输出为 `<code class="language-<slug>">`。 |
| 缩进代码块 | ❌ | 4 空格 / 1 制表符缩进不解释为代码，按段落处理。 |
| 块引用 | ✅ | `> ` 前缀。注意：**每行 `> ` 各自成为独立引用块**，连续多行不会合并为一个引用。 |
| 表格 | ❌ | 不解析，按段落或字面文本渲染。 |
| 分隔线 | ❌ | `---`、`***`、`___` 不会被解释为 `<hr>`，按字面文本渲染。 |
| 定义列表 | ❌ | 不支持。 |
| 任务列表 | ❌ | `- [ ]` / `- [x]` 按字面文本渲染。 |
| 原始 HTML 块 | ❌ | 不被穿透执行，按文本转义（见第四节安全模型）。 |
| Front matter | ⚠️ | 由 CLI 在正文解析**之前**剥离（`---` 包裹的 `title` / `order` / `tags`），不进入正文渲染。 |

## 二、支持的行内语法

| 语法 | 是否支持 | 规则与边界 |
|------|----------|------------|
| 行内代码 | ✅ | `` `code` ``，内容经 HTML 转义。 |
| 加粗 | ✅ | `**text**`。 |
| 斜体 | ✅ | 仅 `*text*`；**下划线 `_text_` 不支持**，会原样显示下划线。 |
| 删除线 | ❌ | `~~text~~` 不支持。 |
| 链接 | ✅ | `[label](href)`；`href` 经安全过滤（见第四节）。 |
| 图片 | ✅ | `![alt](src)`；`src` 经安全过滤。 |
| 自动链接 | ✅ | 仅 `<https://…>` / `<http://…>`；其他 `<…>` 被转义为 `&lt;…`。 |
| 参考式链接 | ❌ | `[text][ref]` 与 `[ref]: url` 定义均不支持。 |
| 脚注 | ❌ | 不支持。 |
| 原始 HTML 行内 | ❌ | 不被穿透，按文本转义（安全模型）。 |
| Emoji / UTF-16 代理对 | ✅ | 0.4.0 修复：整码点输出，单码元切片不再 panic（见回归测试）。 |

## 三、明确不支持（且不会模拟）的语法

以下语法 MoonDocKit **故意不实现**，以免产生「看似渲染、实则错误」的误导：
不保证未来版本支持，也未列入路线图。

- 标题层级 H4–H6
- 有序列表、嵌套列表、任务列表
- GitHub 风格表格、分隔线、定义列表
- 脚注、参考式链接、缩写
- 删除线、下划线强调
- 原始 HTML 穿透（安全考量，见下）

如果你需要这些特性，请在源 Markdown 中改用「受支持的等价写法」，或预处理为
受支持的子集后再交给 MoonDocKit。

---

## 四、安全模型（链接与 HTML）

所有正文文本在输出前都经过 `html_escape`，因此文本中的 `<`、`>`、`&`、引号均被转义，
**不存在存储型 XSS**。

链接 / 图片目标经 `safe_href` 过滤：

- 放行：`http://`、`https://`、`#`（页内锚点）、`./`、`../`，以及**不含冒号**的相对路径（如 `guide.html`）。
- 拦截：`javascript:`、`data:`、`mailto:`、以及其他带 scheme 的非常规 URL —— 一律
  替换为 `#`，不会生成可执行协议链接。

非 http(s) 的 `<...>` 自动链接（如 `<ftp://…>`）不被识别，会作为文本转义。

## 五、如何自行复现这些边界

- **单元测试**：`moondockit_test.mbt` 覆盖标题、列表、代码块、行内格式、链接与
  emoji 代理对；运行 `moon test` 可验证上述「支持」项。
- **边界自测**：在 Playground（或任意示例站点）输入 `#### 标题`、`1. 列表`、
  `~~删除~~`、`<script>alert(1)</script>`，观察其被当作普通文本或转义，符合本节声明。
- **范围漂移预警**：本节任何一项发生变化（新增或移除支持）都必须同步更新
  `CHANGELOG` 与 `tests`，否则视为回归。
